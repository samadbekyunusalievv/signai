SSignAI

The problem

Every chatbot is built for people who can read, type, hear, and speak.

For 70 million deaf signers, that's four assumptions wrong at once. The most powerful AI in history is asking them to use it in a language they're not fluent in — through an interface that ignores the language they actually use.

03 / 12 — Stats
SSignAI

What's broken today

Today's AI is voice-and-text first.

What hearing users get

  • Type or speak in your native language
  • Read or hear the response instantly
  • Voice mode, real-time conversation
  • The full power of the model

What signers get

  • Type slowly in a second language
  • Read replies in a second language
  • No voice mode (it assumes hearing)
  • Captions ≠ sign language

Captions help; they don't translate. Voice modes don't apply at all. Sign language is a real, complex language — and AI products simply don't speak it yet.

SSignAI

How it works

Browser-only V0 — server-light V1+.

Today (V0, single HTML file)

MediaPipe Hands runs on-device, in WASM. A heuristic classifier maps landmark geometry to 8 ASL signs. A mock LLM generates replies. A custom Three.js humanoid plays back keyframed sign animations.

MediaPipe Hands Three.js r128 100% browser No server

Production (V1+)

Replace heuristics with a TF.js classifier (50+ signs), pipe text into Claude or GPT-4o-mini behind an edge proxy, swap the rig for a glTF avatar with mocap-quality sign library, add face/blendshape control for ASL non-manual markers.

TensorFlow.js Claude / GPT-4o-mini glTF + Mocap library PWA / mobile
